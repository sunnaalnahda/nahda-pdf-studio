# جودة PDF ومعايير قبول المرحلة الأولى

## ما تم التحقق منه في بيئة إعداد المصدر

- نجاح 5 اختبارات Python لوحدة المقارنة: ملف غير متغير، كشف فقد stream أصلي، كشف تغير عدد الصفحات، كشف إعادة كتابة غير incremental، وقبول ملف **FreeText** أضافه `pypdf` بتحديث incremental.
- اجتياز فحص PDF مبني من صفحتين بالتحليل والبصرية على 144 DPI عند مقارنته بنفسه.
- مراجعة توقيعات API الموثّقة للمكتبات `pdfrx`, `dart_pdf_editor`, `file_picker`, وذكر تراخيصها في المستند.

## ما لم يُتحقق منه بعد — **لا تصدر النسخة كإصدار مستقر**

لم يتوفر Flutter SDK/Dart أو Android SDK داخل بيئة توليد المشروع، ولذلك لا يمكن ادعاء تشغيل `flutter analyze`, `flutter test`, `flutter build web`, `flutter build apk`, أو تجربة المحرّر الحقيقي على أجهزة المستخدم. اختبار `test/arabic_annotation_integration_test.dart` مكتوب، لكنه **لم ينفذ بعد**؛ لا يمكن اعتماد إخراج العربية حتى ينفذ وينجح في بيئة Flutter.

## خطة فحص أول ملف عربي فعليًا

1. أنشئ نسخة بمحرر Flutter تُدرج `السَّلامُ عَلَيْكُم وَرَحْمَةُ اللهِ` بالإضافة إلى `شركة صُنّاع النهضة ١٢٣ ABC` على عينة متعددة الصفحات.
2. تأكد في Chrome وAndroid من الحروف المتصلة والتشكيل واللام-ألف واتجاه الرموز والأرقام وعدم تداخل السطور.
3. افتح `-edited.pdf` في PDFium وAdobe Reader (للمعاينة المستقلة فقط) ثم قارن الشكل والتحديد والنسخ والبحث.
4. افحص الخط المضمن و`ToUnicode` عبر `pdffonts` أو `mutool` إن توفر (الأخير للفحص الخارجي مع مراعاة ترخيصه)، واستخدم pypdf للقراءة.
5. تحقق من بقاء stream الأصلي، وعدد الصفحات، وأحجامها والتدوير بواسطة أمر:

```powershell
.\scripts\run_quality.ps1 -Before "tests\fixtures\vector_original.pdf" -After "C:\full\path\vector_original-edited.pdf"
```

6. جرّب ملفًا حقيقيًا متجهًا يحوي عربية مطبوعة وأشكالًا وخطوطًا مضمّنة؛ ملفًا مصورًا؛ ملفًا مشفرًا؛ ملفًا به نماذج؛ ومستندًا يحمل توقيعًا رقميًا. سجل الاختلافات والأخطاء، وارفض الحالات غير المدعومة بوضوح.

## حدود المقارنة البرمجية

- مقارنة الـbytes الأصلي كـprefix تثبت **نوع عملية الحفظ التزايدي فقط**، لا تثبت رندرًا مطابقًا أو قابلية البحث عن النص الجديد.
- فحص content streams مُناسب لإضافة تعليقات دون المساس بالمحتوى، **لا يصلح** معيارًا لاستبدال النص الأصلي المتعمد.
- الفروق البصرية المتوقعة تظهر عند مكان النص الجديد؛ وجود اختلاف هناك أمر طبيعي. غياب اختلاف كبير خارج المنطقة مطلوب، ونحتاج لاحقًا قناعًا لمنطقة التعديل وخوارزمية pixel-diff للمقارنة الآلية الصارمة.
- أداة PDFium render هي مقارنة إرشادية، لا تعادل شهادة PDF/A-2 أو PDF/X أو PDF/UA ولا تحقق دقة CMYK/ICC في الطباعة التجارية.

## تحديث التحقق على Windows (11 نوفمبر 2026)

- اجتاز `flutter analyze` دون مشاكل على جهاز المستخدم، وأكد GitHub Actions نجاح الفحص أيضًا.
- اصطدمت اختبارات المضيف `flutter test` على Windows بمتطلب `pdfium_dart 0.4.1` لترجمة مكتبة C صغيرة. هذا لا يعني أن كود Flutter غير صالح للويب وأندرويد.
- أصبح `scripts/bootstrap.ps1` يشغّل فحوص Chrome + `flutter build web --release` افتراضيًا، ولا يتطلب مترجم C/C++ على Windows. فحص PDF الأصلي اختياري عند توفر MSVC.
- ظهر في GitHub Actions تعليق اختبار PDF الأصلي بعد عشر دقائق؛ عُدّل الاختبار من `testWidgets` إلى `test` لتجنّب تعليق `FakeAsync` عند تحميل الخط، ويلزم التحقق من نجاح التشغيل الجديد قبل الاعتماد.
- اختبارات Python مستقلة؛ نجحت في CI، لكنها لا تعوّض تدقيق الشكل العربي الفعلي في PDF بعد الحفظ.


## عربية RTL — عيب FreeText في نسخة المحرر (11 نوفمبر 2026)

كشف اختبار يدوي على Windows أن النص العربي الذي أُضيف بخط Amiri يظهر بترتيب أحرف معكوس داخل مربع FreeText. التفريق مهم:
- **واجهة Flutter** تستخدم RTL بصورة صحيحة، والمشكلة في مسار تشكيل النص المحفوظ/المعروض في مكتبة `dart_pdf_editor 15.0.0` عند استخدام `PdfEmbeddedFont`.
- لا نقلب سلسلة Unicode أو الكلمات يدويًا؛ ذلك يكسر التشكيل والمحتوى المختلط والأرقام وقابلية البحث والنسخ.
- تعطّل الاختيار التلقائي لـAmiri داخل `DartPdfEngine.open`، وتفرض أداة **إضافة نص عربي** استخدام المسار المنطقي Unicode (`activeFont = null`) بدلاً من مسار الخط المضمّن. هذا **حل احترازي محدود** يتطلب تحققًا بصريًا من ملف PDF المُصدّر.
- **القيد:** المسار البديل يعتمد على استبدال خط عند العرض، ولا يضمن تضمين Amiri أو سلامة التشكيل في Adobe/PDFium أو عند الطباعة على جهاز بلا الخط. اختيار خط مضمّن يدويًا من أدوات المحرر الأصلية قد يعيد الخلل.
- يجب حفظ نسخة، ثم إغلاقها وفتحها في PDFium وAdobe Reader، ومراجعة نص عربي مشكّل ونص مع أرقام وإنجليزية. لا تعدّ الميزة صالحة للإنتاج قبل اجتياز ذلك على Windows والويب وأندرويد.
- تحتاج النسخة الاحترافية إلى مسار تشكيل OpenType/GSUB/GPOS (مثل HarfBuzz) وترميز CID/ToUnicode مع تضمين الخط، بدلاً من تعديل اتجاه واجهة Flutter فقط.

أُضيفت فحوص على النص المنطقي قبل الحفظ وبعد إعادة الفتح، وعلى حالة الاختيار الخاطئ للخط المضمّن. هذه فحوص بنيوية لا تكفي لإثبات الشكل المرئي.
